# Phase 4 historical analytics

Version 0.5.0 is the next minor feature release after 0.4.0. Runtime and installed package versions are aligned. Schema remains v5 with 34 tables: existing frozen cohort/discovery records and analysis manifests already express panels and protocols; no migration or redundant metric tables were needed. F1–F9, floor, F19 and F22 implementations remain unchanged.

The contract was written before production implementation in [phase-4-formula-contract.md](phase-4-formula-contract.md). Source formulas remain proposed descriptive designs, without forecasts, causality, final confidence, opportunity scores or public research tools. Registration remains 0/15. No network is used by analytics.

## Internal interface

`HistoricalService(history).analyze(cohort_id, HistoricalOptions(...), video_cohort_id=..., persist=True)` returns the shared AnalysisBundle. `AnalysisRepository.read` and either service's `inspect` accept old and new manifests. CLI: `analysis formulas`, `analysis historical --cohort ID --video-cohort ID --options profile.json`, and `analysis inspect RUN_ID`. These require explicitly migrated storage; listing formulas is offline and does not create a database. A complete synthetic construction is in tests/phase4_helpers.py and the historical tests.

HistoricalOptions records final cutoff, age, goal, tolerance, explicit intervals, old-age threshold (>=90 days), k=5/10, anchor selection/landmark, recent-entry window, creator-group version, auxiliary-provider policy and older/newer Panel definitions. Each Panel records frozen cohort/video-cohort IDs, its historical cutoff, half-open publication window, age/goal/tolerance, discovery run IDs, capability mode, source version and documented coverage epoch/reference. Panel IDs include windows; comparability compares invariant definitions separately so successive windows do not need identical IDs.

## Historical classes and clocks

OWN_HISTORY uses actual exact official view observations and permitted statistical archives. PROVIDER_HISTORY is separate T2 diagnostics. CURRENT_SNAPSHOT supplies at most one point. RECONSTRUCTED_HISTORY remains prohibited. Every observed and available timestamp must precede its panel cutoff; every frozen classification and identity must have been known at that panel's freeze. Future pre-anchor outcomes, later-discovered candidates, current subscribers and re-index dates cannot enter earlier calculations.

Expired API metadata is never revived from statistics. A retained independently supplied chronology claim may provide publication/channel identity when original metadata is unreadable: existing `Claim(field="publication_at", value={"publication_at": UTC_ISO, "channel_id": canonical_ID}, data_origin="independent_annotation", permission_state="permitted", ...)`. It must have been supplied by the frozen landmark, with preserved evidence, source and permission provenance. This does not turn copied API metadata into independent evidence or authorize retaining it. Conflicting independent/official identities stop calculation. Without readable chronology, history remains unavailable. Long-window synthetic fixtures use independently supplied chronology and explicitly synthetic source-scoped statistical permission records, not a claim of actual configured acceptance.

## Equations and units

- F10 exposes per-video own intervals: actual delta/elapsed hours and acceleration as adjacent rate difference. Two points give velocity; three give acceleration. Irregular intervals and negative corrections remain explicit. Duplicate compatible timestamps collapse deterministically; conflicting values/regimes stop the series. Aggregate value is intentionally absent for a bundle of distinct videos; named per-video values carry their own raw numerators and durations.
- F11 is median of channel medians at age a in new cohort divided by that aggregate in old cohort. Absolute/relative changes, video-weighted median, repeat-channel companion, pending/unknown counts, classification coverage and documented independent units accompany it.
- F12 reports observed eligible published videos, active channels, verified entrants and uploads/channel/day separately. Primary active-channel change is (new-old)/old. Search totals are never inputs. Stored occurrence clocks establish discovery; publication date alone cannot backdate recruitment.
- F13 freezes old/pre-existing catalog at interval start, uses actual endpoint differences over >=30 days and divides older increments by all observed scoped increments. New releases start at their first actual observation, never an invented zero. Their shorter exposure makes coverage partial and is disclosed. Younger pre-existing and new releases have separate increments/counts/shares. Negative corrections are retained but suppress contribution-share interpretation. Deleted videos with valid retained endpoints remain usable.
- F20 freezes already-known pre-anchor age-a outcomes at t0, chooses latest k valid pre references and first k actual eligible publications after t0, then computes (median_post+1)/(median_pre+1). Anchor is excluded; later hits remain included. Sequence, maturity, unknown positions, missing uploads, Q25 and goal counts remain visible. It is a non-causal floor/follow-up descriptor. Post-t0 publications differ deliberately from Phase 3's post-anchor-publication repeatability sequence.
- F21 uses creator-group winners meeting G at a in comparable publication panels. Replacement = new-only/new; persistence = intersection/old; entrant winner share = verified recent entrants/new. All three retain separate numerators/denominators, counts, unknown entry bounds and known-only panel flags. Old account age does not disqualify observed new niche entry. Unknown ownership is labeled provisional and is not established independence. An empty winner denominator is undefined.

## Protocol and replay

Stable protocol hash includes stored route/provider/query/filter/locale/language/order/page and result budgets, eligibility/boundary, collection/source versions and capability mode. It excludes run IDs and timestamps. A material change returns unstable_discovery_protocol. Coverage epoch/index expansion or creator-roster expansion returns coverage_not_comparable. Incomplete pagination returns partial_coverage with observed counts only. Equal-duration repeated panels are required for supply/winner change. F11 additionally checks measurement definitions, age and eligibility; F21 checks goal and stable creator roster.

Manifests include all frame/observation/annotation/permission/discovery/provider dependencies and deterministic input hashes. Stored discovery run/page/occurrence hashes are frozen in options.annotation.frozen_discovery; replay also detects mutable discovery-run changes. Results are append-only. Later evidence generates another run; original results are unchanged. Reads recheck expiry and permission revocation. No N+1 reads: frames and discovery/provider history use bulk queries; a 600-video panel test asserts a bounded SELECT count, without timing thresholds.

Auxiliary T2 `nexlev.daily_analytics` records retain daily-series gaps, negative deltas, rebounds, staleness and zero video-count flags. Views/hour, subscribers/hour and uploads/hour remain named separately; no series is repaired. Provider VPH, outlier, RPM, revenue, monetization and geography never define canonical history or winners. Provider diagnostics expire with their 24-hour evidence/source/run retention. The optional explicit `provider:nexlev.history` snapshot route is likewise separate; arbitrary proprietary provider snapshot routes are rejected even for that diagnostic.

Shared gates: available, partial_coverage, insufficient_history, insufficient_same_age_history, insufficient_panel_history, unstable_discovery_protocol, coverage_not_comparable, pending_maturity, source_conflict, policy_permission_required and provider_history_only. Zero denominators yield undefined values with raw zero counts. Pending/unknown never become misses/zeros. Coverage flags are metadata, not a confidence model.

H1–H12 synthetic scenarios are indexed in tests/fixtures/phase4_histories.json and implemented through actual repository observations, frozen cohorts, independent chronology and scoped synthetic permissions. They are arithmetic fixtures, not empirical YouTube claims.
