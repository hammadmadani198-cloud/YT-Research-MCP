# Phase 8 release contract

Defined after verified Phase 7 preflight and before implementation changes or live validation. Starting HEAD/tag: 61305079c14f3196e1b28a517079f9bad7e29820. Preflight: all 18 checks, 818 tests, two real stdio tests, 15 tools, schema v7/36 tables, integrity, Ruff and frozen guard pass. Nine prior bundles are hashed and preserved. Source and request receipts are in phase-8-source-receipt.json.

This is integration and release hardening. C01-C93, F1-F23, F17 sorting only, F18 ordinal confidence, eligibility, cohorts, known-at-time semantics, provider trust classes, recommendation states and the 15 tool names are frozen. A methodology defect requires a report and explicit future revision; no equation patch is allowed here. No previous migration, historical report, tag or bundle may change.

Package target: 0.9.0, following the existing minor-per-phase convention. This is a release candidate, not stable 1.0.0. Schema remains v7 unless an evidenced storage defect requires a separately documented new migration; documentation alone never justifies one. Windows/Python 3.12 is the validated platform. Dependencies remain pinned unless an identified issue requires a justified upgrade and regression/lock update.

Required order: offline acceptance, internal security/privacy review, official provider contract refresh, controlled live smoke, real-niche Quick workflow, final affected regression, source checkpoint/backup. Reading local code while preflight runs is allowed; no live call may precede the safety gates.

Current credential presence precheck: YouTube=false; NexLev=false. Keys are never printed/persisted. Recheck presence before the live gate. Missing keys do not authorize alternate credentials, implicit .env loading, remote MCP OAuth or another provider. Real smoke and niche validation remain unverified if keys stay absent. Policy/storage acceptance is separate from an API key and is never invented for validation.

Live limits if configured: evergreen public channel/video; start with at most one channel and one video request, retries disabled for smoke; an optional documented low-cost NexLev public endpoint. Every attempt gets a receipt. No raw live payload fixture commits. The real niche then uses Quick ceilings (25 channels/250 videos, two search pages), with approximate lower targets 15/100, no guarantee of completion. No Deep run, owner OAuth/private analytics, undocumented endpoints, direct NexLev MCP OAuth experiment or automatic collection. Release-test watches are disabled after testing; immutable evidence is not deleted to beautify results.

Final classification: release_candidate_verified only if applicable mandatory gates including live validation pass; release_candidate_with_live_provider_gap if all local gates pass but credentials prevent live verification; release_blocked for failed release-critical gates. NexLev absence, no scheduler/owner OAuth/off-device backup and Windows-only verification are documented limitations. Do not equate low research confidence with a code failure or high confidence with creator success.

The final phase-8-results.json and live-call-receipt capture exact results and retain failed attempts. phase-8-verified and the new Phase 8 bundle/manifest identify the final source; earlier bundles/tags are preserved. PROJECT_STATE preserves the entire original Phase 0-7 handoff suffix. No host/global settings, automatic startup, scheduler or remote deployment are authorized.
